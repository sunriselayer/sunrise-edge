## Decision

Use the complete responsibility-owned
[encrypted recovery contract](../encrypted-recovery-closure.md) as the single
byte/limit/interface specification:

1. Reuse original signed-genesis, current history/cut and all four explicit
   predecessor roles for every ordered link: exactly `3 + 4L`. Retain external
   trusted pins and expected current cut/package identities independently;
   derive current policy only from the existing verified chain.
2. Compose `pack-saved`/`open-saved` in a small native operator owner. Capture
   once into private staging, verify that stage using existing core factories
   and encrypt the same bytes. On open, authenticate the complete ciphertext,
   close raw inventory and reverify original proofs before qualification.
   SQL import remains a separate existing composition that independently
   reexecutes proofs on every create/resume.
3. Add bounded opt-in constructors/history entries in the existing SDK owners.
   Install the same invocation budget before staging validation or any walk;
   count all roles, ignored staging orphans and every repeated walk before
   descent/collection growth. Check claimed height/component work before
   allocation. Add only a scoped attached-regular-file no-follow/nonblocking
   leaf there, not a generic facade. Ordinary genesis symlink and common
   Ed25519 behavior remain unchanged.
4. Candidate encryption is maintained synchronous binary age 0.12.1, exact
   version and default features disabled, with one typed X25519 recipient and
   separate disposable identity. No handwritten crypto, passphrase/SSH/plugin/
   armor/async/keyring path or plaintext fallback. A caller-owned borrowed
   quota reader uses a real one-byte read on the SAME held unbuffered cursor
   for a nonempty TOTAL-phase decoder read at the exact ciphertext cap, BEFORE
   plaintext EOF if requested: only actual zero returns zero; any byte is
   counted as cap-plus-one and immediately refuses opaquely. HEADER exhaustion
   remains quota refusal. Final authentication, nonempty plaintext EOF, another
   explicit same-file physical EOF and unchanged before/after stamps remain
   mandatory; no reset/clone/reopen/seek/buffer bypass or early qualification.
5. Choose only LOCAL magic `b"SE-RECOVERY\0"`, u16 big-endian version 1 and the
   contract's closed Manifest/File/Footer and seven role tags. No protocol
   registry allocation or change to embedded canonical frames. Exact manifest
   indices/body lengths/raw hashes/footer totals and all framing overhead
   count against quotas; no caller paths or serialized verifier capability.
6. Bound and zeroize owned identity input with maintained zeroize buffers and
   borrowed UTF-8. Display, Debug and the entire source chain expose only fixed
   opaque errors, never retained raw secret-bearing provider/IO errors.
7. Require exclusive private incomplete staging and absent no-clobber output,
   complete sync and stable attachments. Refuse even identical existing output.
   Failure retains unqualified owned residue, not automatic adoption, retry,
   broad cleanup or a secure-erase promise. No atomic directory or cross-file
   SQLite creation claim follows.

## Consequences and release gates

heavy dependencies. Existing zeroize 1.9.0 is only transitive; no direct edge
is added or resolved by this docs change. Exact package provenance, resolved
graph/features, direct edges, checksums, MSRV, license/advisory review and
measured resource/build costs need explicit future review. No resolution or
protocol-crypto upgrade is authorized.

I/O or opaque verification, reserve disk, prove constant RAM, exclude swap or
qualify ENOSPC. Bounded real-child test ownership and host memory/resource policy
remain separate. Footer/hash/completion cannot authorize inactive import,
freshness, readiness, Seal, live activation or signing. Source token continuity
does not exclude an old physical writer.

and full 64 KiB final chunks, and reject cap-plus-one, truncation, concatenation,

existing compiled import/required recurrence owners. Preserve the seven-epoch
withdrawal delay and every existing inactive/fence/ambiguity/WAL refusal.
