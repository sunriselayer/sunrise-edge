# DR-0232: Bounded recovery failure reproduction

Date: 2026-10-13 (UTC).

## Context

The genuine eight-link encrypted saved-closure acceptance reaches `pack-saved`
only after expensive original and recurrent producer work. The former
filesystem calibration has 151 heights and one-byte bodies; it does not cover
the larger genuine inventories, decoder work or business verification. A
generic quota error is not evidence of which bound failed. Repeating that
producer with another speculative ceiling does not diagnose the failure.

## Decision

The SAME shared SDK
budget retains only its first refusal's static category: observations, heights,
components, file bytes, deadline or explicit admission. Mutex poisoning has a
separate static label if no earlier refusal exists. Poisoned state is inspected
only for diagnosis; charging/checks still refuse and poison is never cleared.
Subsequent checks, zero charges, generic refusal and elapsed time cannot
overwrite the first category. Read-only inspection has no filesystem access,
counter reset/refund or new work admission. It exposes no path, counter,
artifact/provider text, key or proof capability. Generic admission refusal,
including existing held-file cap paths, is not claimed as numeric exhaustion.

The recovery command retains the existing fieldless error and refusal
precedence. On failure it may additionally emit one fixed category label to
stderr. A live-budget failure keeps its original category; operator-local
framing/aggregate/headroom limits are not mislabelled as SDK counter exhaustion.
Success output, canonical bytes, proof factories and terminal marker rules are
unchanged. The diagnostic is not completion or import/serving authority.

The larger physical calibration uses the genuine producer's current15,
plans `[9,30,24,15,15,15,15,15]` and manifests
`[13,34,28,19,19,19,19,19]`:323 heights and2,366 one-byte files, with every
legal component kind. It actually exhausts2,097,152 observations in encryption.
This includes an extra literal-body oracle pass but omits business verification;
it establishes that profile's underfit, not a unique historical failure cause.
Select a finite8,388,608 observation ceiling, retaining2,097,152 and262,144 as
explicit sticky downward controls and exact/+1 ceiling refusal. This permits
four times the observation work/prevalidation name growth, including ignored
orphans. It is not a measured minimum or universal sixteen-link capacity.
All other role/file/height/component/plaintext/ciphertext limits, the300-second
cooperative deadline, acquisition and host budgets remain unchanged. Do not
substitute hidden cross-call inventory caches or weaken body/attachment/proof
checks. Require actual larger mechanical terminal success and genuine recovery.

The compiled acceptance may retain failed-pack DATA in one fresh private
test-owned directory. Only the already-observed closed saved-input roles and

Normal successful cleanup and all original acceptance assertions remain.

Creation, descent and enumeration are anchored to the held private root using
exclusive `mkdirat`/`openat` and NOFOLLOW/DIRECTORY/NONBLOCK/CLOEXEC admission.
Saved directory device/inode/full-mode/UID identities are checked before and
after each prefix operation. Payload and disposable-identity reads require

No descriptor cache or syscall-preemption/global-space guarantee is claimed.

not raw child text or a first-refusal label. Original pack failure remains a
failure after any diagnostic retention, including partial retention/refusal.

## Acceptance boundaries

Require first-refusal and shared-clone tests, bounded reproduction refusal
controls and independently reviewed actual input/argument preservation. A
retained fixture permits focused diagnosis with fresh ordinary budgets; it is
not a passed recovery, signed business oracle, custody result or permission to
adopt a partial output. Genuine full relocation and full required validation
remain mandatory. Keep every failed historical run immutable.
