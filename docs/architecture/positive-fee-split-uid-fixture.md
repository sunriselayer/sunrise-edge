# Genuine positive Split UID fixture

[DR-0270](decisions/0270-genuine-positive-split-uid-fixture.md) selects one
explicit test-only addition to the original
`compiled_conditional_readiness_real_retention_restart_and_distinct_certificate`.
It preserves the complete first-successor workflow, original request A5,
epochs, delays, roles, byte oracles, submission and receipt/restart assertions.
There is no replacement authority constructor or alternate shortened workflow.

The original positive claim obtains its object from the activated target and
its canonical request/intent from the live successor host. The explicit inline
selection additionally prepares three unsubmitted positive cases A7/A8/A9
through that same real host and verified SDK. It does not fabricate row digests,
generation, historical authorization or a current epoch. Ordered status and the
observed nonce remain unchanged through these auxiliary preparations.

A create-only export retains the original manifest and every committed file of
the complete plan-history, business-cut, manifest-history and certificate roles,
the full explicit hash schedule, historical claimant and current context. Each
case retains the complete fee object/ref, asserted hash epoch, terms, canonical
signed leg, real host request/intent and independent original outer/candidate.
Held archive readers check attachment and complete inventories. Nonempty staging,
private key/seed/database filenames, unknown roles, count/byte excess and overwrite
refuse. SHA256 file inventories are provenance, while SDK verification against
the original pinned root supplies authority. The copied archive is independently
reloaded and checked before the index is published last.

Plan-history and manifest-history use the existing held nested archive reader.
Every directory must satisfy the defining ordered-history generated-directory
contract, every file must have its defining relative-file bound, and directory
markers must equal all copied leaf ancestors. Empty or invalid directories,
unknown names, symlinks and nonregular leaves refuse. This is structural
transport closure: syntactically valid nonempty surplus history attachments
are retained. Neither the copier nor the ordinary SDK reload closes the exact
descriptor-derived semantic inventory. SDK verification still supplies the
existing successor authority. Both history roles share
one local read budget of 65,536 observations, 1 MiB per file and 300 seconds, with no
height/component decoding by the copier. The original 16 MiB / 256-file export
limits remain in force. The complete before/after nested inventories must agree.
Cut and certificate retain their flat inventory policy. The selected Python
transport admits canonical history fixed/height/descriptor/component/chunk path
shapes; Rust owns semantic file/offset bounds and each role still independently
verifies its complete SDK chain. No generic recursive archive policy is added.

All direct children are registered before work. Pipe and PTY capture preserves

PID1 holds the sole tmpfs mount after all role children have terminated. It

The attached Docker client must reach actual wait and both physical EOFs, and
the stopped container must have PID0 before removal. There is no evidence copy

failure snapshot without the frozen ready hash remains explicitly incomplete.

UID0 has no `CAP_KILL`. Cleanup records each child PID and role UID at launch,
then forks a narrow no-pipe signal owner that drops to that saved UID using the
existing `SETUID`/`SETGID` capabilities and sends only TERM or KILL to the saved
unreaped child. Each signal owner has its own actual wait/PID-absence record;
no stdout/stderr EOF is invented for it. Three fixed-role regression children
must be killed and reaped under UID12001/12002/12003. All failure cleanup shares
one5-second deadline. Signal, drain, reap, accounting or fsync failures cannot
skip the separate bounded metadata-finalization attempt. Failure drains retain
only64KiB per pipe stream and record observed byte counts and incomplete capture;
exceeding that admission bound kills/drains/reaps within the same cleanup budget
and cannot become a successful complete transcript. Liveness/concurrency uses
non-reaping `waitid` with `WNOWAIT`. An exited child's PID remains held until its
recorded final wait; every actual wait updates the reaped registry before a
later signal can be considered. No `Popen.poll()` may release that ownership.

Missing, revoked or expired phase approval controls require the exact existing
public `no_approval` stderr, nonzero exit and absent destination. They do not
match the internal Rust enum spelling. Each service retains two close-on-exec
handles: its original run directory and an `O_PATH` handle for its socket.

the saved service has actually been waited and its PID is absent may cleanup
unlink its exact previously observed path/device/inode/UID/mode socket through
the held directory. Unknown, replaced, aliased or active socket state refuses.
Both handles close on every cleanup outcome, and signal owners close inherited
copies before changing UID. File-only volume accounting remains strict. These
fixture records add no child, host operation, capability or resource allowance.
