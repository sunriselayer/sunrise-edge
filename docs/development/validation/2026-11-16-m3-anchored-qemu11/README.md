## Actual result

Fresh attempt `qga1116f` exited successfully after 29.25 seconds. Its
[terminal receipt](terminal.json) has SHA-256
`3b7c1d1a114513c6e0427864faa9a3c05a2c5af96b13a1a1b11d1ce706b4c8a4`;
the complete [raw log](raw.log) has SHA-256
`60a9bb5cd0fa22f5ead31c6e99746b1b2b711e58e6085082bd3f5b25f0b321f5`.
[Per-VM stream hashes](vm-streams.sha256) cover all 18 fault/recovery boots.
Each cold guest test exited 0 after comparing all twelve structured and two
blob tables, two authority tables, four collections and two positive bodies.

| Case | Actual cold outcome |
| --- | --- |
| `ack` | Acknowledged new state; fresh fence, replay and work succeed. |
| `prepared` | Old state with Pending; three real anchored opens safely stop. |
| `pre-finalize` | New source with Pending; normal open reconciles then continues. |
| `source-write`, `source-flush` | Old state with Pending; safely stop. |
| `prepare-write`, `prepare-flush` | Old source; coherent authority permits continuation. |
| `finalize-write`, `finalize-flush` | New source; reconciliation and continuation succeed. |

All six EIO cases recorded an armed typed blkdebug rule, the selected device's
`BLOCK_IO_ERROR` and actual SQLite COMMIT extended error `1034` (`IOERR_FSYNC`).
The flush-only cases therefore meet the required fsync error condition; the
write-only cases accept this actual writeback behavior under DR-0266. The
controller kept the original authority image attached for cold recovery and
never attached a forensic copy.

The actual cgroup had `memory.max=1073741824`, `memory.swap.max=0`,
`cpu.max=100000 100000`, `pids.max=128`. Peak memory was 827,494,400 bytes;
aggregate guest time 20.04 seconds; generated bytes 1,646,814,649 (<2 GiB);
aggregate retained bytes 3,061,927,562 (<3.5 GiB); gross logical I/O
3,965,135,654 (<8 GiB). All 39 owned children reached EOF, were reaped and
had no remaining PID; all 18 QMP sockets and the cgroup disappeared. No host
mount or cleanup error remained. The independent evidence review found no
actionable fault, oracle, pin or cleanup gap.

An initial current-host attempt `qga1116c` failed before product code because
the task-owned initramfs archive omitted the `usr/lib` directory entry. A
separate `ack` diagnostic `qga1116d` and nine-case diagnostic `qga1116e`
passed after adding that entry. The failed and diagnostic attempts remain
separate from this selected-owner result; none was counted as its success.

This result closes only the local virtual guest fault-boundary child of M3.
It does not prove physical host/firmware/media/fsync behavior, other-host
writer failover, partial persistent WAL writes, production deployment or the
M3 parent. Its source and profile are not silently transferable to later
release qualification.
